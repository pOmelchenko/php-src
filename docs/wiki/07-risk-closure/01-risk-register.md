# Risk Register

Status values are final for this phase: RESOLVED, MITIGATED, DEFERRED,
ACCEPTED, or BLOCKED. No item remains unresolved.

| ID | Risk | Severity | Likelihood | Consequence | Options | Decision | Status | Evidence | Tests | Residual risk |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| RISK-001 | Overloading `protected(namespace)` with descendant semantics | High | High | Voters and implementers confuse namespace descendants with inheritance-protected semantics | Use it; rename descendants; defer descendants | Use `protected(namespace)` for class-level namespace subtrees, but document and vote the terminology conflict explicitly | MITIGATED | Current member RFC reserves `protected(namespace)` Future Scope for namespace plus inheritance; bounded-context use case needs subtree access; see [03](03-syntax-decision.md) | `T-SYN-PROTECTED-ACCEPT`, `T-PROT-CHILD-ALLOWED`, `T-PROT-PREFIX-DENIED` | Internals may reject the spelling; fallback is a non-`protected` subtree syntax before discussion |
| RISK-002 | Conflict with `private class` file/private-block draft | High | High | Namespace RFC occupies syntax intended for name-mangled private declarations | Plain `private`; qualified `private(namespace)`; attribute | Use only `private(namespace)`; keep `private(file)` possible | RESOLVED | Private classes/functions RFC uses plain `private class` for compile-time name mangling and lists namespace visibility as separate future work | `T-SYN-PRIVATE-CLASS-NOT-V1`, `T-SYN-PRIVATE-NAMESPACE-ACCEPT` | Parser/tooling must learn qualified modifier |
| RISK-003 | Scope too large for a first RFC | High | High | Incomplete implementation or hidden unspecified behavior | Exact class only; exact class-like; descendants; explicit root | Choose class-like declarations with exact private and protected subtree; keep explicit root/API consistency out | MITIGATED | [02](02-minimal-scope.md) revised after bounded-context feedback | `T-SCOPE-CLASS`, `T-SCOPE-INTERFACE`, `T-SCOPE-TRAIT`, `T-SCOPE-ENUM`, `T-PROT-CHILD-ALLOWED` | If enforcement gates fail, RFC can drop explicit interfaces/traits/enums or subtree before discussion |
| RISK-004 | Ambiguous boundary: construction-only, symbol visibility, or object membrane | High | High | Users cannot predict operations consistently | Construction/linking only; symbol visibility; object membrane | Use class-name symbol visibility; already obtained objects are not a runtime membrane | RESOLVED | [05](05-operation-coverage.md) defines one invariant and explicit non-probing exceptions | Operation matrix `OP-*`; object tests `T-OBJ-*` | Existence probes reveal symbols by design |
| RISK-005 | Namespace is not a module/package/security boundary | High | Certain | Intentional code can redeclare the namespace and gain access | Claim ownership; add modules; document non-goal | Treat as fundamental namespace-based limitation | ACCEPTED | Externals module discussions repeatedly note namespaces are names, not ownership | `T-SEC-NAMESPACE-SPOOF-DOC` documentation test only | Not suitable for untrusted-code isolation |
| RISK-006 | Namespace descendants add new hierarchy semantics | Medium | High | Prefix false positives and root ambiguity | Include descendants; segment-aware compare; defer | Include descendants only through `protected(namespace)` with segment-aware comparison; defer explicit root | RESOLVED | Bounded-context users need subtree access; prefix collision PHPT passes | `T-PROT-CHILD-ALLOWED`, `T-PROT-PREFIX-DENIED` | Global-root and explicit-root semantics remain future scope |
| RISK-007 | Runtime overhead on public classes | High | Medium | Hot class operations regress | Central check; flag fast path; no runtime feature | Require public fast path and benchmark gate | MITIGATED | Gate 5 found and fixed the large public cache-hit regressions, class-entry storage overhead, and the `public_instanceof` VM-handler layout regression; after-fix paired rows pass the `<= 3%` threshold; the 2026-06-23 trait-body metadata compile/link measurements also pass; see [11](11-performance-evidence.md) | `benchmark/ns_visibility_gate5.php`; [11](11-performance-evidence.md) | Microbenchmark evidence is retained; representative application benchmarks remain useful future evidence but are not a Gate 5 blocker |
| RISK-008 | Load/cache order changes access result | High | Medium | Allowed first use caches CE and denied later use succeeds | Cache by caller; recheck on hit; avoid caching restricted CE | Check before cache population; do not store restricted CEs in shared hot caches when the caller namespace can vary | MITIGATED | Gate 3 validates VM cache behavior; Gate 4 validates OPcache CLI, file cache, namespace ranges, optimizer shortcuts, and preload/linking behavior; the JIT validation gate covers function JIT, tracing JIT, namespace ranges, and inheritance/linking behavior | `ns_visibility_runtime_new_cache_order.phpt`, `ns_visibility_gate3_operations.phpt`, `ns_visibility_opcache_cli.phpt`, `ns_visibility_opcache_namespace_ranges.phpt`, `ns_visibility_opcache_file_cache.phpt`, `ns_visibility_preload.phpt`, `ns_visibility_preload_linking.phpt`, `ns_visibility_jit_function.phpt`, `ns_visibility_jit_tracing.phpt`, `ns_visibility_jit_namespace_ranges.phpt`, `ns_visibility_jit_inheritance_linking.phpt` | Correctness risk is mitigated; performance impact is tracked by RISK-007 and Gate 5 |
| RISK-009 | Autoload side effects happen before denial | Medium | High | Forbidden access can still run autoload userland code | Manifest metadata; pre-autoload denial; document | Accept autoload side effects in v1; enforce after CE is known | ACCEPTED | PHP metadata is known only after class load for unknown names | `T-AUTOLOAD-SIDE-EFFECT`, `T-AUTOLOAD-CALLER` | No side-effect prevention without a separate manifest/module design |
| RISK-010 | Reflection becomes unspecified bypass | High | Medium | Reflection silently defeats class-name visibility | Full bypass; full enforcement; metadata readable plus construction checked | Allow introspection; enforce instantiation and class-name semantic operations; no privileged bypass in v1 | RESOLVED | Gate 3 keeps ReflectionClass metadata construction allowed and checks ReflectionClass allocation APIs from the call-site lexical namespace | `ns_visibility_class_like_metadata.phpt`, `ns_visibility_gate3_callables_reflection_serialization.phpt` | Reflection can still reveal names and metadata; ReflectionAttribute instantiation remains future scope |
| RISK-011 | Public API exposes restricted types | Medium | High | Public signatures can mention names external code cannot use | Native consistent accessibility; declaration allowed/use restricted; no native rule | Defer native consistent accessibility; declaration-site type use still obeys symbol visibility | DEFERRED | Gate 3 checks parameter, return, property, class constant, promoted property, union, intersection, and DNF type resolution when a CE is resolved | `ns_visibility_gate3_type_positions.phpt`; analyzer recommendation | External code may observe restricted type names in public API |
| RISK-012 | Trait composition and trait body caller namespace | High | Medium | Traits gain or lose access depending on use site without clear rule | Trait declaration namespace; consuming class namespace; mixed | `use RestrictedTrait` checks consuming class; operations written in trait body use trait declaration namespace | MITIGATED | Gate 3 stores lexical namespace on user op_arrays and main-op-array ranges; trait `use` is checked from the consuming class during linking; trait method clones retain lexical namespace metadata across aliases/adaptations, file cache, and preload | `ns_visibility_gate3_lexical_context.phpt`, `ns_visibility_gate3_operations.phpt`, `ns_visibility_trait_body_lexical_namespace.phpt`, `ns_visibility_trait_body_opcache_cli.phpt`, `ns_visibility_trait_body_file_cache.phpt`, `ns_visibility_trait_body_preload.phpt` | Inherited method body coverage remains useful broader-suite evidence |
| RISK-013 | Global namespace ambiguity | Medium | Medium | Empty namespace becomes accidental root for all namespaces | Reject global; exact global; public | Global namespace is normalized empty string; `private(namespace)` is exact; `protected(namespace)` from global has no descendants in v1 | RESOLVED | Runtime check requires non-empty declaration namespace for protected descendant matching | `T-GLOBAL-GLOBAL`, `T-GLOBAL-NAMED`, `T-NAMED-GLOBAL` | Future explicit global-root semantics must be defined separately |
| RISK-014 | `::class` and string names | Medium | High | String production either autoloads unexpectedly or bypasses later checks | Check `::class`; never check strings; check semantic use | `C::class` remains string production without autoload/check; later CE-resolving operations check | RESOLVED | Aligns with current class-name constant behavior and avoids new autoload | `T-CLASS-CONST-NO-AUTOLOAD`, `T-CLASS-STRING-NEW-DENIED` | Restricted class strings are visible |
| RISK-015 | Aliases remove visibility | High | Medium | `class_alias()` creates public-looking name to restricted CE | Alias widens; alias denied; CE metadata preserved | Visibility belongs to `zend_class_entry`; alias does not widen | RESOLVED | OPcache notes and CE model share one class entry for aliases | `T-ALIAS-ALLOWED`, `T-ALIAS-DENIED`, `T-ALIAS-CACHE` | `class_alias()` may reveal existence |
